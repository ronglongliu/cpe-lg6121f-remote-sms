# 烽火云短信开发技能

## 固定范围

- 目标设备：烽火 FiberHome **LG6121F** CPE；已有本地实机固件记录 **RP0108**。
- 仅处理账户登录、绑定设备筛选和由用户主动发起的短信手动读取/发送。
- 不是完整远程控制 App。禁止引入 ZTE/MU5120、Wi-Fi/网络设置、状态读取、重启、解绑、远程删除短信或固件升级。

## 关键原则

1. 打开主 README 与 `文档/开发记录.md`，区分既有整合版已确认能力与新拆分库尚未验证的状态。
2. 只读、静态核对优先；默认不登录账户、不发云请求、不触发验证码或发短信。任何真实账户/短信验证需用户明确要求并在其授权设备上进行。
3. 登录、读短信、发短信均必须由用户显式调用；永不加后台轮询或自动发送。
4. 只有三个协议命令允许进入远程执行：`SMS_UPGRADE_MESSAGE`、`SMS_GET_MESSAGE`、`SMS_SEND_MESSAGE`。不得提供通用 command/RPC 方法，也不得从服务端内容拼出额外命令。
5. 按设备返回字段检查烽火命令、响应封装、返回命令和设备状态；登录成功不能推断设备在线或短信可用。
6. 短信发送成功只记为“云端/设备接受请求”。未经独立送达回执核验不得显示“已送达”。
7. 手机号、验证码、密码、令牌、MAC、设备序列号和短信正文不得写入测试快照、日志、截图或 Git。
8. 保持 HTTPS、禁用重定向和 Cookie 自动共享、限制响应大小、账号令牌设备级 Keychain。不要把证书信任降级成任意服务器接受。
9. Objective-C 源码用 iOS SDK 做 `clang -fsyntax-only`；离线夹具仅用合成账户与响应；提交前跑 `tests/离线边界检查.py`。
10. 文案与报告需中文，清楚注明型号、固件、来源、OpenAI 辅助开发、当前不足和未验证事项。

## 公开版本现况

独立客户端的设备选择、认证、短信 RPC 尚未对云端做真实验证；不代表厂商已批准非官方客户端。现有整合项目中，短信功能曾由用户实际确认可用。不得把这一历史状态写成独立库的新回归结果。
